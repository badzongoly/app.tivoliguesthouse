# Expense Corrections

Open **Finance & Cash → Financial Corrections → Expenses**.

## The normal workflow

1. **Select the expense.** Check the supplier, original cost, recorder, original activity, current effective position and actual settlement.
2. **Enter the correction.** Choose amount, category, Cash/MoMo or reference, or an evidenced duplicate. The form previews exact effects immediately. Explain the error and submit for owner review. PDF, JPEG or PNG evidence up to 2 MB is optional.
3. **Eugene decides.** Verify independent evidence, then approve and confirm, return for revision, or reject. Approval records one linked adjustment in today's open period. It does not send or return money.

Staff request corrections only for their own recorded expenses. Eugene can review authorized sources and explicitly approve his own request. Other administrators do not automatically receive his authority. Private reasons, proposal versions and files remain available only to the requester and Eugene.

## Choose the right correction

- **Amount:** Enter total cost actually incurred and total actually paid, not a difference. This phase supports verified fully-paid ordinary expenses where those totals agree.
- **Category:** Change the ordinary operating category while preserving total cost, payment, payer and reference facts. An unresolved payout does not become verified through a category change.
- **Method / reference:** Correct Cash/MoMo or the actual transaction reference, preserving total cost and payout. It changes recorded classification, not a wallet balance or physical money.
- **Duplicate:** Verify one actual cost and payout entered twice, and select its retained expense. Both original records and reference reservations remain. Two genuine payments are not a duplicate record.

A supplier refund, overpayment claim, unpaid balance or actual recovery is separate. Do not reduce a real payment to make it disappear or record a supplier recovery as room/extras revenue. This screen provides a review handoff; it cannot post those money movements.

## Recorder and actual payer

The recorder is the person entering an expense or payment. That person is not necessarily the one who paid.

When recording a new ordinary expense settlement, **Actual Payer (Optional)** lets you identify an evidenced payer. Leave it unknown if it has not been established. The recorder stays separately attributed. This optional field does not create a new payment or alter anyone's privileges.

Older payments are not backfilled from their recorder. Amount, method and duplicate corrections remain blocked when actual payer, destination, evidence, separate cash funding or a single matching settlement cannot be established. Category-only correction can preserve those unknown facts. Incorrect payer attribution itself requires separate reconciliation.

## Requests and decisions

**My Requests / All Requests** retains pending and returned cases. **Owner Review** shows pending decisions. Returned cases can be revised and resubmitted by their requester; earlier proposals/files remain. The requester can withdraw an unposted request. Rejected and withdrawn cases create no financial adjustment.

A changed source, keeper, payout or dependency invalidates the preview. Return it for revision and verify current facts. Do not repeatedly approve stale details. If a submission is interrupted, retry the same action with its original operation key and the same evidence file if requested.

## What remains fixed

Original expenses, payout events, reference claims, actors, dates and closed snapshots are retained. Corrections appear separately on their posting dates. A closed-period-only report therefore keeps its earlier total; the current open period contains the linked adjustment. Current effective source details show the resulting position across periods.

For an erroneous GHS600 record supported by GHS400 cost and payout, the linked cost/outflow adjustment is -GHS200 and management profit effect +GHS200. Actual money moved by the correction is zero. Category changes affect category breakdowns; method changes affect recorded payout classification. Guest receipts, room/extras revenue, stock and full sales-cash deposits remain unchanged.

The expense ledger and its existing limited CSV keep original entries and labeled adjustment legs. Vendor, invoice and description searches retain those legs; totals cover all matching ledger entries. The existing export remains limited to the displayed maximum 300 entries. Weekly and monthly views are different views of the same postings, not two adjustments.

Payment Log distinguishes original payouts and recording adjustments. Adjustment notices show source facts, authorization and zero actual money movement without private case notes/files.

## Stops and scope

Linked purchases/stock and approved provider costs now use [Purchase & Provider Corrections](PURCHASE_CORRECTIONS.md). Assets, payroll, actual supplier monetary recovery and dependent allocation reconciliation remain separate. Independent matching or recovery blocks unsafe money corrections. Unknown legacy methods/custody, differing actual cost/payment, an inactive category or current closed posting period also require resolution.

A compensated duplicate remains linked to the retained collection and cannot be resurrected. Later supported corrections use the current effective retained source. An incorrect duplicate decision requires separate reconciliation.

No new migration or activation is required beyond existing finance/HR, private evidence storage and designated owner configuration. After correction events exist, preserve them and use coordinated forward repair; do not roll back a single reader/writer or delete financial history.
