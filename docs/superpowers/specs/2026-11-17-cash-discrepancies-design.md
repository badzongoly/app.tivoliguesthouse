# Cash & MoMo discrepancies: implementation decisions

Approved direction: extend existing deposit, wallet matching and cash handover records. Staff report a difference; the owner records evidenced partial/full credit, failure/reversal or returned cash. Named cash recipients acknowledge their own actual received portions. Reporting alone never moves money. Original amounts, identities, evidence and closed snapshots stay unchanged. No write-off, invented payment or physical cash count.

Use an idempotent append-only case per source; source identities: deposit finance event, payment receipt, income finance event, or cash handover event. Visibility is restricted to the configured owner and original involved staff. A source hash includes original facts and dependent events; case version includes case and source changes. Recheck under the same security_state lock already used by all finance/handover writers. Retain active-source uniqueness even with new keys.

Case states derive from source amounts: unresolved, partially verified, fully verified; returned cash leaves its original sales-deposit obligation due. Reported or reopened disputes remain open until owner evidences the outcome. Follow-up owner/comment/date remain on the same case. The owner may revise findings with an appended event, never deleting history.

Deposit: record each evidenced credited portion, leaving the rest in transit; return only uncredited dispatched cash to its original evidenced custodial portions; reverse only currently verified portions into disputed transit. Source allocation is deterministic and bounded. Existing nonzero-fee sources remain reportable but partial amount/reversal/return posting is blocked pending separately supported fee reconciliation; do not silently convert fees to missing cash or change earlier approved fees. Unknown original custody blocks cash return.

Receipt: record independent partial credits, full verification and reversed verification while retaining the original receipt and guest debt evidence. A disputed receipt creates no physical cash. Recording a verification reversal alone is not receipt correction, guest refund or new recovery collection; link subsequent work to existing correction/recovery workflows. Every new credited reference must be unique across existing finance claims, aliases and receipts; existing original reference can only be adopted for its exact source and not credited twice. Retain references after reversal. Full resolved verification updates unmatched reading without fabricating another guest payment.

Handover: only the named recipient can acknowledge the actual partial amount. Sender residual stays reserved until remaining acknowledgement or owner-supported return. A return releases reservation under the original sender, without adding cash already held there. Original source allocations and next-day deadlines remain. Existing full acknowledgement/dispute writer blocks once this resolution workflow owns the source, preventing mixed decisions.

Financial commands require today's open day/week/month and current source/version. Reports/follow-up annotations can be recorded without rewriting a locked original period. Audit + business event + operation result commit together. Same key/same fingerprint returns original event; changed payload rejects; different keys still cannot duplicate decisions or over-consume balances. Replays re-authorize visibility and owner decisions. Files use existing encrypted private evidence with authorized download.

Normal path stays one source form plus an owner confirmation; no extra main menu. Evidence files optional, supported reason/evidence reference required for changing verified balances. Staff see exact source status and history, not other cases. Old ordinary confirm/match remains available for untouched sources. Dedicated case screen includes actor/time, partial amounts and open residual; closed original totals remain fixed.
