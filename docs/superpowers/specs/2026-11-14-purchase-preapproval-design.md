# Approved Purchase & Expense Pre-Approval

Owner approved tivoli-purchase-preapproval.html for implementation on 14 November 2026. Implement operating expenses, stock purchases and service providers with request, Eugene-only capped approval/revision, commitment, delivery and actual cost, owner posting, verified partial Cash/MoMo payments and append-only history. Quote/evidence files are optional PDF/JPEG/PNG up to 2 MB. Missing receipts require an explanation of alternative evidence. Only the requester and designated owner may inspect workflow details/files. Use individual accounts and server-side privileges, not names.

Approval is not payment or an expense. Changes require a new decision before further commitment. An actual over-limit cost or payment predating approval is an explicit after-the-fact exception; accepting the cost does not rewrite prior approval. Disputed declarations remain visible and can receive append-only clarification. Cancellation only before commitment. Stock delivery is a complete single delivery in this slice. On owner confirmation, stock quantity and one linked movement update atomically with one expense. All purchase types use one existing expense record, not an additional provider cost. Multiple payments settle that cost without counting it again. Claimed already-paid funds require owner verification and create one payout, not another physical payment. Cash costs never reduce full sales-deposit obligations.

Keep closed dates/weeks/months fixed. If actual activity date is locked, an owner-authorized linked posting uses the current open date and retains the original date. No generalized refund, amount correction, advance-before-delivery or partial delivery workflow is introduced. Preserve legacy source IDs and history. No schema migration or new roles/dependencies. Existing migration-010/finance/owner setup remains the baseline. All dynamic verification targets the exact marked synthetic database/service. No ordinary database writes, production deployment or Git state changes.

Implementation rulings. Preserve the existing uncommitted source checkout rather than creating an incomplete worktree from the old baseline. New ordinary expense/provider/stock-receipt public forms lead into purchases and deny obsolete direct POSTs. Existing declarations/posted expenses/provider requests retain reads/review/settlement. Trusted legacy service interfaces remain available for existing setup and regressions, not as public alternatives. Provide Report Cost Without Prior Approval as an honest exception intake rather than inventing retrospective prior approval. Cost corrections and reimbursement of staff advances are not implied. A reported payer is captured separately from the owner who records settlement. Metadata/file claims and original source links prevent duplicates where evidence exists; do not guess that similar costs are the same transaction.

Final implementation boundary: unapproved historical stock is not accepted as a new stock receipt. Report its missing cost as a cost-only Operating Expense, citing the existing movement/count and original proof in the narrative. No inventory is added or old movement linked automatically. Actual mixed/partial payment methods derive from settlement events; the expense method remains the posted expected/declared method. Financial ledger rows remain visible to authorized ledger viewers while private purchase details are redacted for non-owner administrators.
